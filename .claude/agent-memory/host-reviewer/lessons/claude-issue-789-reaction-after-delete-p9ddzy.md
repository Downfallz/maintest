# host-reviewer lessons, #789 PR

- A "record still there" check before a side file's first write is check-then-write: BlobArtifactStore.DeleteAsync lists then deletes in name order (reactions.json, seen-*, table.json), and AdminApi's QuiesceAsync drains the run, not TableReactions/TableVisits in flight, so a write that passed the check lands after the listing and survives; ask for a re-check after the write and a conditional delete of what was written (#789 PR).
- PlayedTable is added to the registry (and bumped to the lobbies) before `RecordAsync` lands (LobbyApi.cs ~376-389, TableHost.cs:376-377): a guard that reads a missing table.json as "deleted" and latches (TableReactions `_gone`) can latch on a table being born; await the run's pending record write before reading, or do not latch (#789 PR).
- Reactions store failures are not caught at the route (TableApi.ReactAsync calls SendAsync bare): an IOException/RequestFailedException becomes 500 Host.Unexpected (no text since #692), not the documented 503 Reaction.Busy; every new store read inside SendAsync adds a site (#789 PR).
