- A "gone" latch set by a 404 after a tagged read (TableReactions `_gone`, TableVisits `existed`) covers only a file read once: a run deleted before its first reaction or visit still gets the file created by the expected-null write; check the never-written path on any "do not bring the run back" fix (#739 PR).
- Cloudflare never caches a POST and, by default, no extension-less GET path: `NotKept` on `POST .../scenario.zip` or `GET .../export` is defence in depth; check method and extension before calling a missing Cache-Control a leak (#752 PR).
- A refusal reused for a new cause (`Reaction.Busy` 503 "Try again" for a deleted run) keeps the page retrying where a terminal code (409, which the page reads as unavailable) would stop it: check how the page maps the status, not just the code (#739 PR).
