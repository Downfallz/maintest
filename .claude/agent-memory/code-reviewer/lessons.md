# code-reviewer lessons (one line each, with where they came from)

- A summary's "all clear" line must be gated on every input being known, not just on nothing being red: unknown read as green (W6 digest, branch ccr-f0346c35-lt9ro4).
- A try/catch that covers two reads names the wrong one as unread when the second fails: one attempt per field shown (W6 digest, branch ccr-f0346c35-lt9ro4).
- GitHub list endpoints with per_page and no pagination truncate silently; /issues also returns pull requests (W6 digest, branch ccr-f0346c35-lt9ro4).
- A skill meant for a scheduled session with no repository attached cannot be loaded there: the task prompt is the real code, keep it in the repo (W6 digest, branch ccr-f0346c35-lt9ro4).
- An alert or count keyed on a substring of a log line must be grepped against every writer of that text: the startup banner and a sibling worker said it too (W7 ops, branch ccr-1ce109bf-fut95m).
- A Bicep value that moves on every deploy (`utcNow()` into a budget's startDate) must be checked for being updatable in place, not just valid on create (W7 ops, branch ccr-1ce109bf-fut95m).
- A cumulative counter (RestartCount) read with Maximum over a window measures the replica's lifetime, not the window: a "per 15 minutes" alert on it fires as long as the replica lives (W7 ops fixes, branch ccr-1ce109bf-fut95m).
- A word-scanner's exclusion heuristics must be run against the doc's own "Before" examples and against a probe of what they hide: the terminology test exempted lowercase "speed" that the doc lists as legacy, and lowercase sentences as class lists (W8, branch claude/stage-ai-workflow-plan-iczarz).
- An agent prompt that names a heading, label or path must be grepped for it: `sessions`/`decision-times` headings and the `proposal` label did not exist (W8, branch claude/stage-ai-workflow-plan-iczarz).
- A new file under a directory the tests copy to their output (scenarios/, linked by a csproj glob) reaches every test that reads that directory, not just the new ones: grep tests for the old file name and its id to find exact-list assertions (O2 tutorials, ScenariosApiTests.cs:371, branch of d1bf084).
- A JSON shape with an array of records (StepShape[]) lets `[null]` through as a null element: dereferencing it throws NullReferenceException, which the readers' InvalidDataException/JsonException filters do not catch (O2 tutorials, ScenarioFile.Lesson, d1bf084).
- A background answerer that coalesces change signals (busy flag + "again" flag) must not drop "again" on a refused attempt: the refusal is often caused by the very change that set it, so the next question goes unanswered and the script head goes stale (O3a TutorialPlay.AnswerAsync, branch ccr-ae1caee5-8hruvs).
- `TutorialPlay.GaveBack` was raised inside `TutorialPlay._gate` (#646); since #658 it is raised after the gate is left, so a test asserting the event right after polling `Assisted` empty races it: poll the event itself (#658, 6925f69).
- The branch can move while you review (the author session keeps pushing): re-run `git log origin/main..HEAD` before reporting and re-run the tests on the final HEAD (#612/#613/#615, 21748d4 -> 034f8ea).
- Widening a path-scoped rule's `paths:` to a new folder makes every line of it apply there: read the rule against the folder (pages.md "no build step" now covers showcase/, which has build.mjs) (#613).
- A "replace the destination" guard keyed on two file names (index.html + _headers) still wipes a folder that has those plus anything else: prefer a marker the build itself writes (#613, showcase/build.mjs).
- A masker keyed on the shape of a log line must be grepped against every writer of the free text, not just the writers named in the issue: the void explanation (`voided by X (cat): text`) slipped the `by X[.:]` rule, and free text with a newline becomes a second console row with no prefix to key on (ops names, #624, branch fix/ops-report-names).
- A masking rule keyed on `by <word>` must be probed with framework exception text, not just the audit lines: `Connection reset by peer.` became `by <joueur>.` (ops names, #624, report.mjs unnamed, branch fix/ops-report-names).
- `Console.SetOut` in a test races every other class that does it, since xUnit v3 runs classes in parallel: three Cli.Tests classes now swap the global writer with no shared collection (ops names, #624, PlayersApiTests/OperatorVoidTests/TableTendTests).
- When the browser suite runs in the checkout, gate a copy instead: `git archive HEAD | tar -x` into the scratchpad, copy `table/battle-build` in BEFORE `dotnet build` (the Cli bundle tests read it from the build output), symlink `battle/node_modules` for `npm run build` (O3b, branch ccr-56e5b0ba-aqo26a).
- A static gate shared by every instance (`JobsApi.Passing`, a static SemaphoreSlim) makes parallel test classes collide: JobsApiTests and AdminApiTests both POST the tend route, and the loser gets 409, which `GetProperty("run")` turns into a KeyNotFoundException. Grep tests for every caller of a route guarded by a static (#649, branch fix/649-tending-pass-flake).
- A test that swaps `Console.Out` outside `[Collection(ConsoleOutput.Name)]` came back in #649 (after #624): second time; belongs in `.claude/rules/tests.md` (fix/649-tending-pass-flake).
- The checkout can hold the author session's uncommitted edits (`git status` dirty while HEAD is unchanged): build and test a `git archive HEAD` copy, never the checkout, and never swap files in the checkout for a red check (#658, 6925f69).
- Moving an event's raise out of a lock: grep every test that counts the event right after waiting on the state the lock guarded; they now race the raise (#658, TutorialPlayTests late-answer test).
- Text templated from rule values must redo the engine's arithmetic, not the obvious one: floor on a double multiplier (`ResolutionRules.Multiplied`), and every value the sentence silently assumes (a "hit of 7" on the reference creature also reads its Defense). A hand-written "which cards move with which value" map enshrines a missed coupling instead of catching it (#651, branch fix/651-concept-card-numbers).
- A "vanished id" check whose history is the branch's own generated file (`previous` = committed `table/rules.json`) is erased by deleting the file and rebuilding, and CI compares the PR with itself: take the history from the base branch (R1 rulebook, ccr-86d2ba84-kl8u3m).
- A hand-rolled Markdown subset that claims to refuse what it does not know must be probed with `* `, `+ `, `---`, setext `===`, `##x`, an unclosed `**`, a titled link, a wrapped line starting `2.`, and `{1/0}`: each built clean as a paragraph, a list or "Infinity" (R1 rulebook, scripts/rules/build.mjs).
- Second time (W8, then R1): a word scanner that exempts lowercase legacy words lets player-terminology.md's own "Before" lines through ("Choose speed"): run every new scanner against that column (R1 rulebook, retiredWords).
- A redirect added to the lobby's load (the first tutorial opening by itself) must be checked against every intent the address carries: `?next=` was guarded, `?rematch=` (lobby.js:262) and `#learn-to-play` were not, and the spec mock answering no `opens` hides it (O4, branch ccr-80be3737-czvtwn).
- Second time (O2, then R1 feedback): a posted array of records (`"errors":[null]`) deserializes a null element and the projection's `.Message` throws NRE, answered 500 with the exception's text; belongs in `.claude/rules/host.md` (R1 feedback, FeedbackApi.cs:162, 14f3eca).
- An address guard that reads `CF-Connecting-IP` first is spoofable whenever the Cloudflare-only ingress fence is off, and `onlyCloudflare` defaults to false in infra/main.bicep: check the fence before trusting a proxy header (R1 feedback, TableServer.AddressOf, 14f3eca).
- Rate guards that read the store then write (count, then save) run unlocked because HttpHost answers each request on its own Task.Run: parallel POSTs pass every guard together, and a merge's read-modify-write loses the other's addition (R1 feedback, SendFeedback, 14f3eca).
- Second time (#658, then R1 feedback): the author session edited the checkout while I reviewed (HEAD unchanged, tree dirty with fixes and a sibling reviewer's memory): review HEAD from a `git archive` copy and say which findings the uncommitted tree appears to address (R1 feedback, 14f3eca).
- Second time (#651, then R2): a templated example draws the buff but assumes the base stat is 0 (Defense, critical chance): grep every Defense and criticalChance expression for its `creature.` term, and every "no spell applies" claim for a check that holds it (R2 rulebook, rules/03-the-round.md).
- A "last N days ending today" window counts today's partial day, scales it into a month's estimate, and leaves the rest of today to no later window: end a recurring window at yesterday (M1 minutes, workflow-metrics.py completed_runs, branch ccr-fc0eecc1-oomeh5).
- Paging a live newest-first list (Actions runs of today) by page number shifts items between pages: dedupe by id; and a per-run fan-out (one /jobs call per run) must be sized against the token's rate limit (GITHUB_TOKEN: 1,000/hour/repo) (M1 minutes, branch ccr-fc0eecc1-oomeh5).
- A CI job given a `name:` (a matrix's `battle release (<profile>)`) must be grepped against `scripts/workflow-metrics.py`'s JOB_GROUPS: the rename filed the release minutes under "other" (M2, ADR 0190, 00a47f8; fixed in 250b318 with a test reading the name).
- Narrowing what a pull request plays (release=webkit) must keep the full set for the paths that define the narrowed job (its workflow, its Playwright config, plan.js): otherwise the PR that edits release-desktop's job or project never runs it before main (M2, ADR 0190, plan.js).
- Second time (#612 range, then M2 00a47f8 -> 250b318): the author session pushed a fix mid-review; re-read `git log` before writing any finding up, not only before reporting.
- A new item in the shared navigation (`table/navigation.js`, `headerContent`) breaks `lobby-home.spec.js`'s exact list of visible items and its desktop overflow check: run `lobby-home.spec.js` on every project when the header changes (R2 feedback).
- The branch moved twice during a review again (#612, M2, R2): diff `<reviewed sha>..HEAD` before writing up a finding.
- A shard count chosen to separate heavy specs must be checked with `playwright test --list --project=... --shard=i/n` on HEAD (fullyParallel splits the ordered test list into contiguous chunks by count): M3 said the two halves put battle-live and battle-playback together; `--list` showed 1/2 and 2/2 split them, and 3 shards put both in 2/3 (M3, d057201).
- Folding or removing a CI job: grep the docs for prose that names it ("their own job" in docs/learning/training.md, ADR 0013), not just its `name:` in workflow-metrics.py (M3, d057201).
- Folding a job into another as a `continue-on-error` step: read its position against the steps before it (an earlier failure skips it, outcome `skipped`, so the run no longer says both), and split its commands (`bash -e` lets the first failure hide the rest: ruff drift hid pytest and Sonar's coverage) (M3, fac1573b).
- A matrix entry chosen by `--grep` on top of the plan's narrowed spec list passes empty with `--pass-with-no-tests` but still pays a runner, the deps and the battle build: in a minutes plan, count the empty jobs a narrowed PR now spins up (M3 `desktop replays`, fac1573b).
- A page that reverses a built list for "latest first" (`changes.reverse()`, `.at(-1)` as latest) trusts an order the build neither sorts nor refuses; with one entry no test can tell: sort by the field, or make the build refuse disorder (R3 rulebook, table/rules.js:243).
- A worker fallback widened from "no network" to "5xx" applies to every file in its list, shared styles included: every page, not just the one the ADR is about, then gets an older deploy's copy (R3 rulebook, table/sw.js unanswered).
- Third time (#658, R1 feedback, R3): the tree moved mid-review on the coordinator's word; re-grep each finding against the current file before handback, and say which were checked.
