- A Playwright `page.on('response', async ...)` handler is not awaited: what it parses can land after the page drew the same body, and two overlapping reads can resolve out of order (`latest` goes back in time). Collect in the page (an `addInitScript` fetch wrapper that reads a clone before handing the response back) and read it in the same `evaluate` as what the page showed; battle.loop.js:212 and battle.tutorials.js:153 still hold the old shape (#903/#908, f562b70).
- An in-page fetch wrapper keyed on a path suffix must be checked against the page's stream routes: a clone's `.json()` on an event stream never resolves and holds the page's own stream; `/api/seat/<seat>/events` and `/negotiate` miss `endsWith('/api/seat/player1')`, so it is safe here (#903/#908, f562b70).
