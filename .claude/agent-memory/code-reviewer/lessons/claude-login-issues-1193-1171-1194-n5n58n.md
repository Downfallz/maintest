# code-reviewer lessons (branch claude/login-issues-1193-1171-1194-n5n58n)
- A count held in memory and said "on the next request" is lost whenever the table idles to zero (`minReplicas: 0` in infra/main.bicep): ask for a flush when the host stops, and a test of it (#1171, SignInCounts.Due, 73c1217).
- A pull request that closes the plan's "Left:" items must rewrite those lines too: sign-in-methods-plan.md kept "Left: ... (#1171)" and P3's "Left: the Discord journey ... per network address" after closing #1171, #1193, #1194 (73c1217).
- A flush on stop put in RunAsync's `finally` is proven by cancelling the token (Ctrl+C); the platform's stop (SIGTERM to PID 1) goes through `AppDomain.ProcessExit`, which needs a test of its own or the production path is unproven (f37708d).
- A per-address count "of refused sign-ins" also holds the malformed (400), unavailable (503) and in-flight posts when the take is before the parse and only the vouched ones are given back: read the doc's word against every exit of the route (f37708d).
- A cap counted at settle time (refusals noted once the provider answers) is bypassed by concurrency: every post admitted before the first settles; a per-network cap over many sub-keys must count in-flight posts too, or it is unbounded (155d098, SignInAttempts.PerNetwork).
