# code-reviewer lessons (branch claude/issue-1232-stores-conditional-writes-l149y2)
- A version-keyed text cache that skips a pre-write read also skips the pre-write refusal: a hit over a moved version is sent and refused by the storage (412), so "refused without being tried" doc comments go stale; read each doc line against the hit path (#1232, ae6defe).
- A round-trip saving proved on one adapter (Blob, a counting pipeline policy) leaves its twin adapters (File) with the same change and no test that breaks when it is reverted; ask for the twin's test or say it is a guard only (#1232, ae6defe).
- A per-instance cache cleared in the adapter's `ForgetAsync` is cleared only in the process that erases: the API erases, while the worker and tend open their own stores (`ArtifactStores.Open*Async`) and keep what their reads cached. Grep the composition root for every process that opens the store before accepting "erasure lets go of it" (#1232, 4ed2fc1).
- A cache filled on every read and emptied only by a write keeps whatever the read-only callers read (`ListAsync` to send pushes, the inbox list): ask what the cache holds after reads that write nothing (#1232, 4ed2fc1).
- A guard added "after" a line that already does the same thing "before" (Forget before and after a delete) is untested by any test that does not interleave a read between them: revert the new line alone and see if a test breaks (#1232, a8142bf).
- A lifetime enforced by a sweep that runs "at most once a lifetime" at the next use bounds nothing in an idle process and lets a text live up to two lifetimes in a busy one: read a "let go at the next use" doc against the sweep's own throttle (#1232, a8142bf).
