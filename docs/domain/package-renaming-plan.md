# Package and spell renaming plan

## Goal

Rename the evolution packages and their spells so they read as **mutations or forms a creature becomes**, not RPG classes a creature takes.

Narrative rule:

> The mage forces the creature to mutate during combat. Each package is a new form or direction of evolution.

The intended player-facing structure is therefore:

- **Tier 1:** broad mutation family
- **Tier 2:** specialized mutation state
- **Tier 3:** iconic final form

The internal mechanical vocabulary remains separate from the names. Package identity tags describe gameplay; package and spell names carry the fantasy.

## Naming principles

- Prefer names that describe a creature, state, mutation or final form.
- Avoid occupation/class language when possible.
- Avoid French translations that rely on awkward hyphenated fantasy compounds.
- English and French do not need to be literal translations if a more natural equivalent preserves the same fantasy.
- Keep names short enough to scan quickly in the evolution tree and spellbook.
- Tier 3 should feel like a destination, not just “Tier 2 but stronger”.
- Spell names should reinforce the package fantasy without overselling the mechanic.
- Stable ids and spell mechanics should not change just because display names change.

## Tree naming

Preferred player-facing name:

- **Mutation Tree**
- **Arbre des Mutations**

It names the **Tier prerequisite graph** rather than the authored `Talent tree`, which groups a Creature definition's Spells and no longer decides what Evolution may buy (ADR 0056).

## Implementation notes

This document locks the intended **player-facing naming**, but does not rename stable ids.

A later implementation change should:

1. keep current tier/spell ids stable;
2. introduce or update player-facing EN display names;
3. add French localization at the presentation layer rather than encoding French into domain ids;
4. update tree/catalogue/card labels and spellbook references;
5. keep package identity tags separate from the names;
6. update docs/screenshots/examples that still use previous names;
7. verify saved references, balance knobs, simulations and prerequisites still resolve by stable id rather than display name.

No gameplay numbers or mechanics are changed by this naming decision.
